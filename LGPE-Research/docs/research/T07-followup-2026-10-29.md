The pinned local pkNX source is commit
`d191cd0e5c05f2af81d9a41c1f1d82e6621b351a` (GPL-3.0). In its
`pkNX.Game/File/GameFileMapping.cs`, `GetMapping` selects `FilesGG` for `GP`,
`GE`, and `GG`; the `FilesGG` mapping exposes `bin/pokelib/item` as the item
folder. `pkNX.WinForms/MainEditor/EditorGG.cs::EditItems` then filters that
folder to files whose *individual file length is exactly 36 bytes* before
calling `Item.FromBytes`. `pkNX.Structures/Item/Item.cs` defines `Item.SIZE` as
`0x24`. The separate `ItemHash` entry for
`bin/pml/item/item_hash_to_index.dat` appears in the `FilesSWSH` mapping, not
`FilesGG`. That other-title mapping does not establish the layout of the
similarly named LGPE file.

The repository batch code follows that LGPE editor boundary in
`src/lgpe_research/batch.py`: item files are candidates only when their
individual size is exactly `0x24`. Each of these three files was also passed
directly to `gamedata_decode.item` from the repository's current decoder; each
raised `ValueError: pkNX GameManagerGG item records must be exactly 0x24 bytes`.
The decoder emitted no JSON for them, and the expected mirrored outputs
`decoded/1.0.2/romfs/bin/pokelib/item/{battle_pocket,field_pocket,item_hash_to_index}.json`
do not exist. A 36-byte item-record interpretation was therefore rejected
rather than applied to unrelated byte streams. No schema for the three files
is asserted here.

## `item_hash_to_index.dat` cross-version candidate probe — 2026-10-29

The exact local source is 16,740 bytes, SHA-256
`a9050fef634aa1bc2dfe34cd48781bc6357498f05133e2ac63a463be2b5f9fc0`.
The pinned pkNX source at commit
`d191cd0e5c05f2af81d9a41c1f1d82e6621b351a` contains
`pkNX.Structures/Item/ItemHash8.cs::GetItemHashTable`. It reads a 32-bit
little-endian count, then 16-byte rows containing a 64-bit value, a 32-bit
value, and skips the last four bytes. `GameFileMapping.cs` places the matching
`bin/pml/item/item_hash_to_index.dat` path in `FilesSWSH`; the only source call
found is in `EditorSWSH.cs::Randomize`. This is SWSH evidence, not an LGPE
decoder declaration.

I added the explicitly cross-version-only mode
`itemhash-probe <path>` to `scripts/gamedata-crosscheck/Program.cs` and ran the
actual pinned C# `ItemHash8` implementation against the local LGPE file using
the Windows .NET SDK 10.0.403. Reproduce from the project root with:

```bash
"/mnt/c/Program Files/dotnet/dotnet.exe" run \
  --project scripts/gamedata-crosscheck/crosscheck.csproj -c Release -- \
  itemhash-probe '../1.0.2/2b7730a9e56498bbafac2002d4908c6b_NCA/1/bin/pokelib/item/item_hash_to_index.dat'
```
