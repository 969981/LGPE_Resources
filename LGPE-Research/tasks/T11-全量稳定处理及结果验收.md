# T11 — 全量稳定处理及结果验收

**优先级：** P1  \n**依赖：** T02 T04 T06 T07

## Codex 子任务提示词

请先阅读项目根目录的 `AGENTS.md`、`CODEX_MASTER_PROMPT.md` 和此文件。你负责 T11：全量稳定处理及结果验收。**不能只写计划或只生成框架**，必须推进到实际验证，若源资源/工具不可用则准确记录阻塞和已完成的独立部分。严禁改动 `../1.0.2/`、添加游戏数据到 Git。

### 执行步骤

1. 将已证明可处理的格式作为白名单批跑；先 20→100→全部兼容文件，注意磁盘和 CPU 配额。
2. 每批生成 success/failed/unsupported/retryable、来源哈希和输出尺寸汇总；损坏文件独立失败不阻断其他工作。
3. 运行 `uv run lgpe verify`，随机抽检不同目录同类格式；核查目录映射与不同扩展名冲突。
4. 开发 `report` 或 JSON 报表：按原始扩展名/引擎类型/目录/转换方法统计覆盖率，显示真实进度。

### 验收门槛

- [ ] 复现命令完整、处理比例准确、可重跑且不触碰原始输入；失败列表包括可采取行动的原因。

### 交接输出

将样本路径、原始文件哈希、工具源码 commit、原始/导出签名、测试命令、运行结果、失败明细、后续接口写入 `docs/research/T11-notes.md`；修订 `tasks/INDEX.md` 和 `docs/research/STATUS.md`，提交单独的 Git commit。没有完成真实试解时只能填 `IN_PROGRESS/BLOCKED`，不可标记为 `VALIDATED`。
